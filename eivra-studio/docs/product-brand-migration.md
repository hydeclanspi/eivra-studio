## 数据与会话兼容

所有浏览器存储操作统一经过 `src/lib/brandStorage.js`：

1. 优先读取现有 `eivra.*` / `eivra:*` 值。
2. 新键不存在时读取对应旧键，并尝试逐字节复制到新键；不解析、重写或合并用户内容。
3. 新写入使用新键。旧值作为迁移时的恢复副本保留；它不会随新写入更新。
4. 明确删除草稿或锁定会话时清除新旧两个别名，防止旧草稿、旧令牌在下次读取时复活。
5. 如果复制遇到容量限制，旧值仍可读取；新写入失败会抛回调用者，不伪报保存成功。

预览数据仍保持原有内存隔离。旧标识集中在 `shared/brandCompatibility.js`，回归测试中另外保留必要的旧格式样例。

旧 JSON / Excel 备份仍可导入；新 Excel 元数据使用 `eivra_excel_backup`。加密算法、密钥、快照字段与合并规则不变，新封装使用 `eivra_enc_v1`，旧封装继续可解密。新旧时光快照 schema 均可读取。服务端同时接受新旧客户端请求头，JWT 的 scope、有效期与原有访问行为不变。

## 保留的外部兼容入口

- **已有 Supabase 表。** 默认继续连接现存快照表，名称通过兼容模块提供。仅替换表名会切断旧快照，故本次不执行远程数据库结构变更。将来实际迁表并验证数据、索引、权限和历史客户端后，可设置 `VITE_EIVRA_SNAPSHOT_TABLE`；GitHub 保活工作流须同步设置仓库变量 `EIVRA_SNAPSHOT_TABLE`。
- **旧图片 URL。** `vercel.json` 保留旧头像地址到当前图片的内部重写，兼容缓存中的旧页面与外部链接。
- **来源与历史。** 原始资料名称和旧说明保存在不可修改的归档中；当前 genesis 数据仅更新来源描述，业务数据不变。
